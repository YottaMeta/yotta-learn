# 元习复杂场景走查（按归位模型）

> 旧版走查围绕 `.learnings/` 记录；本版按「归位决策树」重写：先判断去向，再落到对应载体。完整模型见 SKILL.md「使用模型」。

## 走查 1：命令失败后的「踩坑 → 修复 → 沉淀」

场景：PowerShell 里一条含反引号的 node 命令执行失败，根因是外层引号把反引号吃掉。

1. AI 复述失败现场：命令、报错、根因。
2. 归位判断：这是跨项目通用的踩坑（shell 引号处理）→ 属于「可复用知识」。
3. 写前查重：`kb query 引号` 确认没有同题条目。
4. 写入草稿：`kb add --category <dev-tools> --title "PowerShell 外包 node -e 的引号坑" --message "摘要 + 根因 + 规避写法（先落临时脚本）" --source "session 2026-10-12"`。
5. 证据齐后 `kb review <ID> --pass --evidence "本次修复实测通过"`；下次开工时 `kb query 引号` 直接命中。

## 走查 2：用户纠正后的「事实修正 + 边界」

场景：用户指出"默认不会读 .agents/skills"，此前记录写反了。

1. 归位判断：这是跨智能体通用的事实 / 红线 → 写元忆 FACT（长期红线再加机器级锚点），不进 KB 当"方法"。
2. 写入后回读确认；若 KB 中已有错误条目，用 `kb update` 更正或 `kb deprecate` 停用。
3. 周级 review 时确认同类错误没有反复出现；反复出现说明应升级为门禁 / 清单（技能化）。

## 走查 3：外部接口故障的「降级判断」

场景：调用元忆超时，但本地记录不能断。

1. 归位判断：故障现场属于运行事实；稳定下来的降级路径属于可复用方法。
2. 故障现场写项目文件（或元忆 FACT）；「外部故障 A/B/C 降级」方法若尚未沉淀，`kb add` 草稿 → 核验入库。
3. 元忆恢复后补写关键事实，避免把"依赖故障"和"学习内容"混在同一层。
